# D2.0 — Commissioning Frame

Deliverable D2.0 (WS-T2) under DEC-0015. Frame for Regime 1 per Section 5A of
`docs/governance/TOR_test-capability_RevC_RULED_2026-08-10.md`.

Authored 2026-08-11. **Status: RULED by the operator, 2026-08-11.**

Ruled on a green pre-flight verified that day from a non-elevated harness shell, all
four assertions: non-elevation of the invoking shell, corroborated by two independent
methods; ONNX and chromadb cache traversal, by traversal and read of the extracted
model; service availability, with the container runtime and database port reachable and
the vector store evidenced present, readable and writable; and conda environment
identity (`arcaai`, Python 3.11.15). That pre-flight was red on first run; the root
cause and the constraints it places on the D2.2a pre-flight artefact are recorded at
`docs/governance/FINDINGS_2026-08-11_onnx-acl-root-cause.md`.

Ruling authority: the operator, directly. Amendments after ruling are themselves
governed acts.

Scope: the D2.2a runner spike commissioning session. A further commissioning session may
adopt this frame by a one-line operator ruling citing it, rather than re-authoring it.
That adoption ruling must name the specific session it adopts for: no adoption is
open-ended or standing. Re-adoption is valid only while this frame text stands
unamended — if the frame is amended, the amending act states whether prior adoptions
carry, and silence means they do not. Extending this frame on any other basis is an
operator ruling, not an assumption.

Held to one page by amendment 8 of `docs/governance/RULINGS_RECORD_2026-08-10_TOR-test-capability.md`
— five parts, nothing else. It must not grow into a miniature Test Plan.

## 1. Session objective

Prove the harness mechanism end to end: one retrieval scenario, spec file in, corpus
queried at a pinned snapshot, result JSON out.

## 2. Entry criteria

- **Pre-flight green**, all four assertions passing: non-elevation of the invoking
  shell; ONNX and chromadb cache traversal; service availability for the vector store,
  and Docker where a serving-layer dependency is touched; conda environment identity
  (`arcaai`, Python 3.11.15). Pre-flight failure exits non-zero immediately and blocks
  every downstream step — there is no partial entry and no partial ledger record.
- **Corpus snapshot pinned and stated** in the run record: the snapshot current at spike
  time. This session does not wait on the listing act, and the snapshot it pins is not
  required to be a listed one.
- **Scenario spec schema-valid** against spec schema v0.1.
- **Working tree state recorded**: branch and HEAD sha, with the tree clean or its
  modifications stated.

## 3. Exit criteria

- A result JSON is produced.
- That result is reproducible from its triple: spec hash, model version, corpus
  snapshot.
- **The scenario's own pass/fail is NOT an exit criterion.** Commissioning proves
  plumbing, not the system under test. A failing scenario whose result JSON is
  reproducible from its triple satisfies this frame; a passing scenario that cannot be
  reproduced from its triple does not.

## 4. Records rule

- The run artefact is ledgered carrying the regime marker **COMMISSIONING**, in the
  ledger entry and in the result artefact itself.
- Anomalies are observed-not-raised into the session record: noted as observed, not
  converted into findings or fixes mid-run.

## 5. Admissibility rule

Results produced under this frame say nothing about the system under test and are
**inadmissible as gate evidence — permanently, not merely until the Test Plan is
ruled**. A commissioning result cannot be promoted retroactively. A scenario whose
result is wanted as evidence is re-run under Regime 2 against the ruled Test Plan,
meeting that regime's entry criteria. No commissioning result appears as gate evidence
anywhere.

End of frame.
