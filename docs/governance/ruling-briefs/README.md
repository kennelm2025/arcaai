# ruling-briefs/ — Tier 2 briefs for the Mobile Ruling Protocol

**Status: ADOPTED AS PILOT (ruled 2026-08-12) — not a permanent rule.** The
Mobile Ruling Protocol runs in this form, with its issue template and the
`ruling-requested` / `ruled` / `desk-only` labels, as a trial.

**Review clause:** after the first **five** mobile rulings have been made and
transcribed, the protocol is reviewed and its permanence decided. Until that
review returns, nothing here is settled practice and no other document should
cite it as established. The review is the operator's, and its outcome is
recorded as a decision entry.

One markdown file per non-trivial ruling request, written by the lead at request time.
Renders in GitHub mobile; mirrored to Mike's Gmail drafts as
"Ruling brief — <issue number>: <title>" for offline reading.

**Filename:** `<issue-number>-<slug>.md`

**Required contents:**
1. Background — why this decision is on the table now.
2. Chain of prior rulings it touches (DEC/ADR/CL/WS-E references, linked).
3. Consequences of each option, spelled out.
4. Links to the actual artefacts (never paraphrases standing in for them).

**Rules:**
- The issue card (Tier 1) links the brief; the brief never replaces the verbatim text on the card.
- If a Tier 3 panel is commissioned, its synthesis is attached to the issue with each model's
  position attributed and disagreements preserved — never blended into false consensus. The panel
  advises; only Mike rules. Panel trail is retained as provenance (SS1/23 decision-making evidence).
