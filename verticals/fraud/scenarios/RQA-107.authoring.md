## Typology re-key — old and new

| Stage | Value | Status |
|---|---|---|
| v0.2 draft | `unverifiable-pending-vocabulary:statute.fraud_act_2006` | **Refused at v0.3** — the colon fails the pattern |
| Interim | `unverifiable-pending-vocabulary.statute.fraud_act_2006` | Passes, but retains a status marker |
| **Committed** | **`statute.fraud_act_2006`** | Plain descriptive identifier |

The marker was **dropped, not merely re-punctuated.** v0.3's pattern enforces
identifier form and its field description states the non-comparability limit in
terms, so the marker's job is now done by the schema. A vocabulary-status prefix
baked into every value would go stale the moment the fraud-side vocabulary lands,
and it is a property of the vocabulary rather than of the typology. All seven
batch-1 scenarios use plain descriptive identifiers on this reasoning.

## From CARRIED-NO-FIELD to structural — what the re-author changed

The v0.2 draft carried four requirements in `description` under a
`CARRIED-NO-FIELD:` prefix because v0.2 had no field for them. All four are now
structural fields:

| Was carried in `description` | Now |
|---|---|
| absolute `top_k` cap, class corpus_qa cap 7 | `retrieval.top_k_absolute_cap: 7` |
| binary-probe justification | `retrieval.binary_probe_justification` |
| Obligation D justification | `retrieval.obligation_d_justification` |
| density-stratified note | `retrieval.density_stratified_note` |

The fifth, the typology identifier, is above. **No `CARRIED-NO-FIELD:` prefix
appears in any batch-1 spec**, which is the migration this schema version
existed to make possible.
